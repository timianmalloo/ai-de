Domain model before UI

Proposed bounded contexts: Intent (WorkItem, SpecRevision, AcceptanceCriterion), Delivery (ChangeSet, Run), Assurance (Assessment, Finding, EvidenceLink), and Decisions (ReviewDecision). Existing workspace/entity identities are references, not duplicated models. WorkItem is a small aggregate whose invariant is that acceptance names one exact spec revision and the required evidence; assessment and decision aggregates pin base/head/content identity and never mutate a prior verdict.

Grain: one evidence-link row is one producer's claim linking one exact criterion revision to one production/test artifact version; one run-result row is one test attempt in one environment; one decision event is one actor's disposition at one baseline. Append-only facts carry changes; stable entities are dimensions. Derive status, coverage and attention from those facts. Counts are additive only within a defined disjoint population; durations across parallel runs are non-additive for wall time; pass/flake/coverage rates are non-additive and retain numerator, denominator and window. Changes to a criterion's meaning create a new revision. Content changes invalidate relevant evidence and decisions; a mockup's authority is exploratory until explicitly selected or approved.

Surface and hard-state inventory

Three destinations share project, scope and selection: Factory; Review; Understand. Six demonstrations: spec-first work/progress, PR review, test worthiness, graph/code understanding, architecture review, and rigor backlog. PR and Tests are Review lenses; architecture is an Understand lens. Code and execution are subordinate evidence, not separate primary destinations.

Every destination renders ready, loading, empty, error, stale, partial, and untrusted-output states. The harness varies persona, viewport, theme, state and reduced motion. Stale evidence blocks decision recording. Sample action buttons alter local demonstration state only; no provider calls, Git operations or production approval occur. The mockup includes keyboard focus, accessible names, a diagram table alternative, zoom and context drill-down, and visible omission counts.

UI triggers: dense desktop analysis and AI uncertainty states apply. The artifact is HTML, so native DPI, UI Automation, WPF keyboard, windowing and packaging proof remain unverified and belong to later implementation. Existing DESIGN.md is reused; no production token or shell change is made.
