Exploratory, not approved. The file inventory and curated source are from TheTerrace at dba2a29c. Diagrams are reconstructed from source, not observed runtime traces. AI interactions remain simulated. Neither TheTerrace nor Claude's product code is changed.

One Architecture destination, not another app. The accepted shell already has Coding, Explore and Architecture. We deepen Architecture's contents and use its planned sidebar icon and retained docking host. “Code Atlas” is the study name, not a fourth perspective.

What the developer should gain

“I can find the file where I would normally start, inspect its real members, understand the larger behavior around them, then open the precise source behind a diagram arrow without losing my place.”

What we should not build

A repository-sized class diagram, an attractive but unverifiable AI architecture poster, or a chat window that makes the user describe a symbol already selected on screen.

The differentiator is not “generate a diagram.” It is ask a better question of the same evidence, and keep every answer connected to its source.

PHYSICAL FILES, SEMANTIC TYPES, ARCHITECTURAL MEANING

Two ways in. Five explicit altitudes.

The correction: revision 1's graph-to-tree toggle was still a small semantic sample. Developers need the actual solution, project, folder and file hierarchy, including files with no semantic representation. A permanent Solution Explorer supplies that grounding; visual navigation is another entrance, not a replacement.

FILE-FIRSTSolution Explorer + source

Real projects, expandable folders, filenames and extensions, an editor and member outline. Step up from a file or member to a class, component or behavior.

VISUAL-FIRSTOverview + entry points

Choose a feature, preserve the concept map, then switch to concrete UML. Descend through members and messages to the code that supports the diagram.

SAME IDENTITYEvidence + return path

Explorer, breadcrumb, class, sequence and source agree on identity and revision. Back restores the previous altitude and branch, not just a node name.

Chosen UX archetype: a linked multi-panel workstation, closest to the technical catalogue's G6. Developers read structure and evidence in parallel, then narrow their scope. This is not a sequential form or a chat-first workflow.

AltitudeQuestionTheTerrace stop
1 · SystemWhat is this application made of?One web product project, test projects, feature folders and the separate Azure deployment view.
2 · Component / featureWhich responsibility matters here?Predictions: UI entry, submission policy, domain model, persistence and lifecycle.
3 · TypeWhat structure and relationships exist?Concept map or concrete UML for Prediction, store/interface, score, amendment and Fixture.
4 · MemberWhat does this operation do?SubmitAsync, SettleAsync and Score: signature, source branches, sequence and supporting calls.
5 · Source lineWhat is the exact code?Actual file text, original line numbers, member outline, source hash and full-file/excerpt disclosure.

A file is not a class: Prediction.cs contains both Prediction and PredictionAmendment; PredictionStore.cs contains the interface and implementation. File, type and member identities must remain distinct. Source navigation cannot simply pick whichever type was first in a file.

Journey 1 — developer: file → member → sequence → source

Solution Explorer → Components/Shared/PredictCard.razor → SubmitAsync. Read the real component, choose the member in its outline, and open the source-reconstructed sequence. Choose the new, revised or closed branch. Activate a message to open its exact call site, then return with Back. Inspect the interface registration before assuming its implementation.

Journey 2 — architect: system → feature → concept → UML → method

Overview → Predictions → Class model. Keep the concept map for orientation. Concrete UML adds visibility, property types, method signatures and interface realization. PredictionScore and amendment associations have EF mapping evidence. A FixtureId field alone is only a logical reference. Select a member and descend to its source body.

Journey 3 — scheduled behavior → settlement → pure function

Settle and score → PredictionLifecycle.RunAsync → SettleAsync → Score. Inspect the intermediate save, the actual scoring formula and the test that describes exact score and correct-result points. Tests are read as evidence, not reported as executed or as coverage.

Journey 4 — cloud layer → named service → declaration

Azure layers → compute, data, secrets, storage and observability. Each component identifies its Azure service family, role, declaring Bicep and connection semantics. AKS and Cosmos DB are examples of service vocabulary, not boxes to invent if absent from this repository.

Make investigation feel continuous

  • Focus + context: pin a component, expand one hop, collapse infrastructure noise, keep selected nodes stable. Offer exact scope controls as well as direct manipulation.
  • Trail, not tab archaeology: back/forward, breadcrumbs, named view bookmarks, and a small set of pinned questions. Restore selection by ID, never by row number.
  • Compare without losing the original: before/after revision, intended/actual dependency, or static/model interpretation. Always identify both input snapshots.
  • Source is one move away: source, evidence and the diagram remain synchronized. Keyboard and list-based alternatives provide the same navigation as the canvas.
  • Explain, don't perform analysis theatrically: show the actual context manifest, processing steps and limitations; never fabricate an AI reasoning transcript.

MACHINE-EXTRACTED STRUCTURE, HUMAN-REVIEWABLE INTERPRETATION

Use the bound model to explain the graph, not invent it

The deterministic path remains useful with AI disabled. Static tools establish syntax, symbols and bounded relations. The model interprets a selected evidence slice. A validator checks IDs, citations and admissible relationship types before candidates can enter a view.

Evidence kindWhat the UI may sayWhat it must not imply
Source-extracted“This resource declaration / type / reference appears at this span and revision.”That the code executed, that an HTTP endpoint is deployed, or that every dynamic edge is known.
Statically inferred“This framework binding / association is approximated by this rule.”That all static-analysis output is exact. Extraction method and certainty are separate dimensions.
AI interpretation“Candidate aggregate root, because of these invariants; counterevidence here.”“Verified architecture,” invented confidence percentages, or silent promotion into extracted facts.
Human-declared / accepted“This boundary was declared by the architect” or “candidate accepted as an annotation.”Observed runtime truth. Acceptance changes review status, not evidence origin.
Runtime-observed, if provided“This path occurred in trace X at time Y.”Exhaustive behavior, all error paths or current Azure deployment state outside that observation.

One analysis transaction

  1. Capture the slice. Workspace identity, commit + dirty-overlay fingerprint, extractor versions, bounded node/edge IDs, coverage and exact source spans.
  2. Preview the context. Show the connected provider/model, the question, selected files and source excerpts, exclusions and budget. No silently selected alternative provider. The bound execution session is not permission for arbitrary repository egress.
  3. Request typed candidates. Use the existing approved harness/subscription boundary after its read-only analysis contract is established. Do not reuse the prompt-compiler's specialized output schema or bypass its guards. No direct SDK path is proposed.
  4. Validate, then review. Require existing source IDs and spans. Reject fabricated IDs, malformed output and claims with missing evidence. Display supporting and contradicting evidence; accept an annotation, edit it, or dismiss it.
  5. Persist reproducibly, if approved. Store the immutable input identity, output, model/prompt version and reviewer disposition; render derived views from that record. A repeat view reads the saved result. “Analyze again” is explicit and may spend again.

Contain nondeterminism

Stable node IDs and deterministic layouts do not depend on a model's wording. Rejected candidates cannot add topology. A changed revision marks dependent interpretations stale. Cancellation or quota failure retains the static slice and any prior result with its old snapshot label.

Protect the boundary

Repository comments, docs and model output are untrusted data, not instructions. No tools, shell execution, deployment or mutations from this analysis path. Redact secrets and respect content exclusions before provider egress. Exports are inert, escaped data and preserve provenance.

Evaluation before admission

A new model-assisted capability needs its own eval fixture pack, not “the model is connected.” Include tiny hand-labelled systems, incomplete repositories, dynamic dispatch, misleading class names, false aggregate hints, unresolved Bicep modules and malicious source comments.

THE FULL CLASS DIAGRAM IS A MODEL, NOT A DEFAULT SCREEN

Scale the question before scaling the renderer

Virtualizing cards alone does not make a dense relationship graph comprehensible. Keep the complete model queryable, but render a bounded semantic slice. The repository has already recorded whole-graph overload (DC-035) and unreadable fixed-layout graphs (DC-036).

LevelWhat is visibleHow to go deeper
SystemProjects or declared components; summarized, typed cross-boundary dependencies.Choose one scope. High edge density offers a dependency matrix instead of another zoom level.
Package / domain candidateCollapsed groups with counts, a few boundary-crossing relationships and unassigned nodes.Expand a single group. Group membership stays inspectable; AI clustering is labelled.
Class neighborhoodA selected type plus chosen inheritance/association/dependency relations. Members folded.Expand one hop, pin a neighbor, hide external libraries or choose a relation kind.
Member / behaviorSelected fields, signatures, contract details and a method's bounded call slice.Open source, follow one call, view a branch, return with selection and layout intact.

Proposed initial design budgets, not measured product limits

  • Default class detail: begin with 6–10 visible type cards, members folded. Separately, propose an initial query ceiling of 24 types / 48 relations. Query capacity is not permission to put every result on screen. Narrow or replace the visible slice as the user explores; validate these budgets at wide and compact widths on real corpora.
  • Each bounded query discloses shown / eligible / omitted / unknown separately. Total unknown is not zero. Member omission and edge omission are independent counts.
  • Retain positions by stable ID for all unchanged visible nodes across one-node additions/removals and snapshot refresh; retain camera and selection as well. Place new nodes locally. Broad movement requires explicit “Relayout.” Before product admission, test before/after coordinates; a deterministic layout alone does not guarantee this stability.
  • Use hierarchical layout for layers and inheritance, swimlanes for behavior, and a matrix for dense coupling. None of these choices removes the readable-card budget.
  • Preserve edge semantics while bundling: an aggregate edge exposes member edges and their provenance. Mixed evidence does not inherit the strongest confidence.
  • Target p95 selection-to-inspector under 100 ms for a cached slice and filter response under 250 ms; measure cold/warm runs on agreed small, medium and large corpora before committing an SLO.
  • Prefer 2D first. A 3D presentation is an optional experiment only if it improves a measured task, with a fully equivalent keyboard/list path.

Diagram notation has to mean what it says

Sequence: participants and messages, explicitly “possible static trace” unless sourced from runtime events. Activity: branch/merge and fork/join only with evidence for those semantics. Data flow: source, transform and sink; a call is not enough. Class: association/inheritance with provenance; use a composition diamond only with lifecycle ownership evidence. ER: keys, optionality and multiplicity from schema, not generic object references. C4: do not mix people, classes, containers and Azure resources at one undifferentiated level.

Keep the limits: the design is historical/pre-pivot and proposed; current administrator UI reachability, caller authorization and later revocation history are not assessed by this sample. The relevant session turn was found, but a matching linked record was not located in the inspected audit/change logs. That linkage gap is displayed, not hidden.

Owner and conductor calls belong in the same chain

A decision card should carry actor and role, authority/delegation, scope, effective order, accepted/rejected status, rationale, supersedes/superseded-by links, audit ID and session turn. Human instructions and properly authorized owner/conductor rulings can explain a difference. A model's unaccepted suggestion cannot silently become the governing requirement. A timestamp alone does not prove authority or causality.

Use the same source/altitude navigation to inspect either side: clause → decision → source method → diagram, and back. AI can suggest mappings and explain discrepancies; deterministic checks and explicit review govern classification. No universal conformance percentage is proposed without an established denominator and assessed coverage.

Functional acceptance examples for the next spec

  • Given a selected type and scope, when I switch graph to tree, then the same ID is selected, or an explicit filtered-out explanation appears.
  • Given unresolved runtime dispatch, when I trace an entry point, then the missing step is visible and no solid “observed” message is fabricated.
  • Given 5,000 eligible types, when the class view opens, then the agreed visible budget is respected and the omitted count is correct.
  • Given a candidate aggregate accepted by an architect, when I inspect or export it, then origin remains AI interpretation and review status records the acceptance separately.
  • Given an unresolved Bicep parameter, when the deployment view opens, then conditional resources stay conditional rather than disappearing.
  • Given AI is unavailable, cancelled or over quota, when I inspect source or pivot views, then deterministic navigation still works.

Quality obligations, not implied by the mockup

Accessibility: native UIA plus keyboard/canvas parity. Reliability: snapshot consistency and explicit incomplete results. Security/privacy: bounded, consented source egress with no tool authority. Performance: measured on agreed real corpora. Maintainability: one projection/selection contract. Observability: named latency, coverage, result-bound and failure emitters. Release/rollback: newly admitted surfaces and AI analysis independently disableable; no destructive migration assumed. Compatibility: versioned view exports, extractor/model metadata and preserved previous snapshots.

Highest-leverage next decision: choose one complete reading journey to make excellent. Recommended: entry point → bounded behavior trace → source + domain context. It connects the requested views into a task rather than launching five unrelated diagram tools.

Why not an all-in-one automatic reverse-engineering engine?

It bundles the hardest language, framework, modeling, graph-layout and trust problems before the first useful workflow exists. A supported slice with visible limits is more useful than an impressive “complete architecture” diagram that cannot justify its arrows.

Why not reuse Explore for everything?

Explore serves broad knowledge navigation; the accepted spec deliberately separates it from code/architecture understanding. Reuse the projection and visualization substrate, not the task identity or a duplicate registry.

What remains deliberately unproven?

Framework-wide entry-point recall, accurate aggregate inference, large-repository layout performance, native UIA/focus behavior, live Azure state, cross-language data lineage and model-quality thresholds. The HTML prototype proves none of these production capabilities. Their admission evidence is specified above.
