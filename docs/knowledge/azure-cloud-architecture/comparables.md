# Comparable solutions & problem framings

Sorted by input class, because input determines the failure mode.

## Reads repository artifacts (IaC) — our class

| Tool | Input | Output | Licence | Does well | Does badly | Confidence |
|---|---|---|---|---|---|---|
| **Bicep Visualizer** (VS Code) | single `.bicep` file | node-link graph in VS Code | Free (extension) | Explicit + implicit `dependsOn` within one file | No cross-module, no `existing`, no ownership, no export | Verified [S14] |
| **terraform graph** | Terraform HCL/state | DOT | Free, built in | Complete dependency graph | Verbose to the point of unreadable; mixes resource, provider and variable nodes | Verified [S28] |
| **InfraMap** (Cycloid) | Terraform HCL or tfstate | DOT → PNG/terminal | Apache 2.0 | Prunes to "most important/relevant"; groups by VPC/region | AWS/GCP-first logic; other providers get raw output; no Azure-specific simplification | Verified [S28] |
| **Rover** (im2nguyen) | Terraform plan JSON / HCL | interactive web UI, SVG | MIT | Interactive module/dependency explorer; highlights plan changes | Terraform only; low maintenance since ~2021 | Verified [S29] |
| **Pluralith** | `terraform plan` | PDF/PNG + CI integration | Commercial, Alpha; API key required | Change highlighting, Infracost overlay, drift detection | Alpha; Terraform only; undisclosed pricing; requires their service | Verified [S30] |
| **Brainboard** | visual → Terraform HCL | diagram + HCL | Commercial SaaS | Visual IaC authoring, diagram-is-code | Terraform only; commercial | Flagged (not fetched) |

## Reads a live subscription — the inventory class

| Tool | Input | Output | Licence | Does well | Does badly | Confidence |
|---|---|---|---|---|---|---|
| **Azure Resource Graph** | live ARM state (KQL) | JSON rows | Free within Azure | Query any property across subscriptions; 14-day change history | Eventually consistent; 15 q/5 s; 10 k-subscription cap; **no edges** | Verified [S5][S7] |
| **App Insights Application Map** | telemetry from instrumented code | interactive call graph in portal | Free within App Insights | Runtime topology, failure/perf hotspots | Needs instrumentation; no infrastructure resources; not architecture | Verified [S20] |
| **Cloudcraft** | live AWS/Azure, or manual | 2D/3D diagrams; PNG/SVG/JSON | Commercial SaaS | Native Azure component library; live import; cost estimation | No IaC import; Azure breadth may lag AWS; closed | Verified (Azure support) [S31] |
| **Hava.io** | live Azure/AWS/GCP | auto-generated diagrams, stored | Commercial SaaS | Continuous sync; documentation emphasis | Not IaC-aware; limited to what the cloud API exposes | Inferred [S32] (marketing content only) |
| **Cloudockit** | live Azure/AWS/GCP/VMware | Word/PDF/Excel/HTML reports + diagrams | Commercial SaaS | Autogenerated documentation across clouds | Reports more than architecture; not IaC-aware; needs subscription access | Inferred [S33] (limited content retrieved) |
| **Lucidscale** | live AWS/Azure/GCP | diagrams in Lucidchart | Commercial (Lucid suite) | Enterprise collaboration | Azure depth unverified — URL failed to resolve | Flagged |

## Authoring tools (no import) — the honest-manual class

| Tool | Input | Output | Licence | Does well | Does badly | Confidence |
|---|---|---|---|---|---|---|
| **mingrammer/diagrams** | Python code | PNG/SVG via Graphviz | MIT | Diagram-as-code, version-controllable; Azure/AWS/GCP/K8s node sets | Manual only; no discovery; Azure node set may lag icon releases | Verified [S27] |
| **draw.io / diagrams.net** | manual + XML | SVG/XML | Apache 2.0 | Built-in Azure shape library; ubiquitous; no lock-in | No live import; manual; shapes may not track the latest icon set | Inferred |

## Adjacent models worth borrowing from

- **Backstage** — the `Component` / `API` / `Resource` / `System` / `Domain` vocabulary with `spec.dependsOn`
  and `spec.owner`. Directly analogous to our service↔resource stitching, already adopted, free to copy.
  *(Verified, [S23][S24])*
- **TOSCA v1.3** — node types, relationship types with semantics (`hosted_on`, `connected_to`, `depends_on`),
  lifecycle operations. Conceptually the right shape; no Azure ecosystem, so adopting it buys a translation
  layer and no community. *(Verified, [S25])*
- **Score** — a clean statement of the *workload* contract ("I need a postgres, I need dns") deliberately
  decoupled from the resources that satisfy it. Useful as an upstream contract, not as a topology model.
  *(Verified, [S26])*
- **C4 deployment diagrams** — the only widely-understood notation that already separates deployment nodes,
  infrastructure nodes and container instances, which is exactly the curation distinction the inventory
  tools fail to make. *(Verified, [S22])*
