# Glossary

| Term | Meaning in this proposal |
|---|---|
| Accepted intent | A versioned outcome and obligations approved by the operator, not an execution permission |
| Assurance | Evidence supporting a bounded claim, with gaps and limits visible |
| Change set | A pinned base/head/content comparison, including dirty content when present |
| Criterion | One independently discussable obligation with an oracle |
| Drift | A discrepancy between authoritative expected and observed versions |
| Evidence link | A producer's versioned relation; confidence and provenance are retained |
| Factory | A local work-item operating model joining intent, runs, change and assurance |
| Guided review | A tour of semantic changes and human questions, with full-diff access |
| Human obligation | A policy or unresolved judgment requiring an identified human role |
| Oracle | A falsifiable observation that distinguishes correct from incorrect behavior |
| Review snapshot | Immutable inputs and assessment used for a decision |
| Test worthiness | Separate obligation coverage, assertion strength, fidelity, efficiency and reliability |
| Static sequence | A code-derived call scenario; not observed runtime execution |
| Rigor backlog | Proposed risks/issues/todos with evidence, consequence, owner and validation |

These are **Inferred local definitions**, aligned with the reference model and existing AI-Forward
vocabulary. Product-specific meanings and source terminology are in the source ledger.
