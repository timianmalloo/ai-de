Reference model — proposed, Inferred

Do not store a second definition of a quantity already derivable from facts. The following is a research-grounded proposal, not a schema migration or accepted architecture.

Object / grainRequired identity and evidenceInvariant
Work item / one accepted outcomeWorkspace, outcome, exact spec revisionAccepted intent is distinct from execution permission
Criterion revision / one obligation meaningStable criterion id + content version + authorityMeaning changes append a revision; history is preserved
Change set / one base→head/content comparisonRepo/worktree/base/head/uncommitted content hashA commit id alone does not identify dirty content
Evidence link / one producer's versioned relationCriterion→code/test/run, producer/version, confidence, locationAn inferred link is not a proven oracle
Test attempt / one test in one environmentRun/execution identity, test identity, attempt, runner/version, environment/window, result, durationRetry recovery never overwrites first failure
Assessment / one analyzer at one baselineScope, inspected/omitted files, failures, cost, findingsPartial analysis cannot become a clean whole-scope result
Review decision / one actor's dispositionExact head/spec/architecture/policy version, reasonChanged relevant baseline makes the decision stale

Version pinning and retained snapshots have documented prior art in CodeRabbit snapshots and Copilot approvals. Explicit spec authority is grounded in Spec Kit persistence.

Baseline and drift disposition

Expected artifact may be accepted spec, architectural constraint, selected mockup, or exploratory PoC. Preserve its authority. Observed artifact may be parsed code/schema, a run or rendered state. An agent comparison records the gap, never silently replaces expected with observed. Dispositions: implementation defect; approved requirement change; obsolete baseline; missing test; ambiguous intent; incomplete evidence. These must lead to distinct next actions.

Security, privacy and local desktop boundary

The source store and normal execution stay local. Optional provider inference and cloud review are explicit egress boundaries, including upload scope, policy, cost and retained evidence. Treat repository docs, diffs, test logs and external reviewer text as untrusted input, not instructions. Approve intent, authorize an action and approve a change in separate controls. A read-only plan does not imply shell/tool containment. Grok caveat, ultrareview cloud boundary, VS Code planning.

Operator questions and emitting sources — proposed

How long/how costly? Run timestamps, token/cost provider receipts, plus unknown when absent. What was inspected? Analyzer manifest with scope, omissions and errors. Why is a human needed? Policy evaluation plus finding/decision record. What changed since approval? Baseline identity comparison. Was behavior proved? Criterion, assertion and executed-run records. How often does it fail? First-attempt result history with environment/window denominators. Never synthesize a plausible zero for a missing measurement.
