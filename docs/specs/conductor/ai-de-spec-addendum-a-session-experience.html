Addendum A — The Session Experience

amends spec v1.0 date 2026-09-09 status normative; supersedes v1.0 where they conflict

Spec v1.0 specified the planes — engines, conductor, coordination, scoring, routing — and left the front door unspecified: how a person starts, what object they are inside, which backends serve them, how they write, and how they read. This addendum specifies that experience: File → New Session into a workspace-bound, two-pane, multi-modal surface with a rich composer on the left and a multi-mode output canvas on the right. It also repairs a vocabulary collision v1.0 created around the word "session".

A2The experience, end to end

  • File → New Session (Ctrl+N). If no workspace is active, the workspace chooser interposes (recent list + browse + create); a session cannot exist unbound.
  • The New Session sheet (A4) collects: name (default: date-slug, renameable later), backends (ACP engines with account/health, MCP servers), routing mode, autonomy, and default policy. One click on sensible defaults — the sheet is one screen, not a wizard.
  • The session opens as a document in the Workbench: composer pane left, output canvas right, in the paired-zone layout from the mockups. The layout is a preset, not a new window type; docking, zones, and persistence behave like every other surface.
  • The person writes in the composer (A5): rich editing, @-mentions that become context-recipe chips, a goal-block mode for T2+ work, staged drafts with explicit send.
  • Output renders in the canvas (A6): default is the merged console across conductor, agents, and sub-agents (the Performance stream with the lane rail); artifacts produced by any lane collect into an artifact list and open in rendered/preview/source/diff modes, Claude-app style.
  • A session accumulates blocks over days; reopening a session restores the surface; restart-from-block and resume behave per spec §7.3.

Naming rule, effective immediately: bare "session" in code, docs, and UI means the user-facing container above. The Watcher's existing session vocabulary migrates to "lane"/"terminal session" opportunistically (no big-bang rename; new code complies, touched code migrates). The markdown projection moves with the log: docs/sessions/<session-id>.md covers the whole session with per-run sections.

A4Entry point and the New Session sheet

A4.1 Commands

  • File → New Session (Ctrl+N) — the primary verb of the application; first item in the File menu.
  • File → Open Session / Recent sessions (sibling to Recent workspaces; entries carry workspace context and switch it on open, with the same prompt-if-dirty behavior as workspace switch).
  • Palette: "New Session", "Open Session…", "New Session in workspace…".
  • A terminal-first path remains: File → New Terminal Session creates today's terminal session untouched — adopting the CLI experience stays one menu item away (spec invariant, preserved verbatim).

A4.2 Workspace binding

Active workspace → sheet opens bound to it (switchable inline). No workspace → chooser first. Never a session without a workspace: backends, graph tools, coordination, and scoring all key on it.

  • Agent backends list comes from the EngineCatalog filtered by provider registry state; each row shows account and live health (ready / needs-login / quota-degraded). Toggling a needs-login engine offers the engine-native login flow inline. Disabled engines are simply not offered to the router for this session.
  • Context backends list comes from the MCP registry (extending McpConfigWriter's knowledge): the workspace graph server is pinned on; others toggle per session and are injected into every governed lane at session-create time.
  • The sheet writes session.yaml; everything on it is editable later from the session header (changes apply to new runs, never retroactively — recorded as a session event).

A4.4 Placement in the shell

A session is a dock document rendered by SurfaceContentFactory into the paired-zone layout preset (composer zone + canvas zone, splitter between). ADR-0017's retain-never-rebuild invariant applies: unparenting the session document (mode switch, tab switch) never disposes the WebView2 surface or any lane. Multiple sessions may be open as sibling documents; exactly one is active for keyboard focus.

A5The composer (left pane)

  • Editor. Rich text in the Claude-app sense: markdown-native editing (live bold/italic/code/lists/fences), multi-line by default, monospace fences with syntax color, paste-as-fence for code, image/file paste-to-attach. Implementation: a web editor inside the session surface (the surface is already WebView2 + React per spec §3) — CodeMirror 6 is the recommended base (markdown mode + decorations for chips); Monaco is the fallback if fence editing dominates. Not a WPF RichTextBox — the rendering stack for the canvas is web; keep one text stack.
  • Context mentions. @ opens a picker over graph nodes, files, artifacts, and prior blocks; a selected mention becomes a chip in the text and a line in the block's context recipe (pinned path @ HEAD, graph query, block ref). Chips are the visible recipe — what you see in the composer is what the conductor gets.
  • Slash commands. / surfaces pack skills and session verbs (/optimize-graph, /prepare-for-coordination, /restart-from, /resume); selecting one scaffolds its block.
  • Two submission shapes. Message (free prose → T0/T1 triage path) and Goal block (structured CT19 editor with the six fields; Tier picker gates ceremony). The composer offers "promote to goal block", and the conductor may answer a message with a drafted goal block for the person to accept — round-tripping into the same editor.
  • Staging semantics lifted from PromptDraftSurface: a draft is never sent by editing; send is one explicit action (Ctrl+Enter); drafts persist across restart per session; unsent draft state is visibly staged. The old Transfer-to-terminal remains available on the same draft via the target selector — composer drafts can feed observed lanes too, one-way, exactly as US-ED6/ED7 specified.
  • Below the editor: the block outline (the Score) — prior blocks with recipes, decisions, and per-block actions (restart from here, branch, open run).

Extraction plan — track 1

Rendered markdown of the plan artifact, produced by the conductor in block b2; provenance footer names the lane, run, and commit.
  • Registration. Artifacts enter the session index from run events: every file.edit/create by a lane, every conductor report, plans, projections, and diagrams. Inline artifact cards appear in the Console at the moment of production; opening a card jumps to the Artifacts viewer.
  • Viewers per type. Rendered: markdown via the canvas's renderer (graph-flavored: mentions link back to nodes). Preview: HTML in a sandboxed iframe (no network beyond the virtual host; scripts allowed for self-contained pages — the pack's own report HTML must render). Mermaid/diagram sources render drawn. Source: syntax-highlighted read-only editor (same CodeMirror stack as the composer). Diff: side-by-side for lane edits and converge merges. Mode availability follows type; the toolbar shows only what applies.
  • Truth discipline. The viewer shows the artifact at its producing commit by default with a one-click "view at HEAD"; stale-vs-current is always explicit. Artifacts are files in the workspace — the index holds paths + provenance, never copies.
  • Actions. Pin (session header), open in external editor, reveal in Explorer surface, copy path, and — for plans and reports — "send to composer" as a mention.

A7Requirements (extend spec §11)

R13File → New Session flowP0

Entry point, workspace binding, and the sheet.

  • Ctrl+N with an active workspace opens the sheet pre-bound; with none, the workspace chooser interposes and cancel aborts cleanly.
  • The sheet lists agent backends from the catalog with live per-account health; toggling a needs-login engine offers the engine-native login without leaving the sheet.
  • Create writes session.yaml, opens the session document in the paired-zone preset, and registers it in Recent sessions; reopening restores composer draft, mode, and layout.
  • File → New Terminal Session still produces today's terminal session, unchanged.
R14Session object and naming repairP0

A3's model in code and on disk.

  • Run logs live at .aide/sessions/<session-id>/runs/<run-id>.jsonl; the session projection covers all runs; spec §7.1 paths are superseded.
  • New code uses "session" only for the container; a lint/doc note marks the terminal-session qualifier rule.
  • Backend toggles apply to new runs only and emit a session event when changed.
R15ComposerP0

Rich editing with staged send.

  • Markdown-live editing with fenced code (highlighted), paste-to-fence, and attach; @-mention picker over files, graph nodes, artifacts, and blocks; each mention materializes a recipe line visible as a chip.
  • Message and Goal-block submission shapes; promote-to-goal-block round-trips; a T2 goal block missing a CT19 field cannot send (field-level error).
  • US-ED5/ED6/ED7 semantics hold: never sent by editing; one explicit send; draft persists across restart; the same draft can transfer one-way to a ready observed lane.
R16Output canvas modesP0

Console default; modes switchable and splittable.

  • Console renders the merged stream with lane rail and tree filtering (mockups v2 fidelity); default on session open.
  • Mode switch is instant and lossless (retain-never-rebuild); canvas zone splits to two modes side by side.
  • A permission request surfaces within one event cycle regardless of active mode.
R17ArtifactsP1

Registry + multi-mode viewer.

  • Lane edits, conductor reports, plans, and diagrams auto-register with provenance (lane, run, block, commit); inline cards appear in Console at production time.
  • Rendered / Preview (sandboxed) / Source / Diff modes per type; producing-commit vs HEAD is explicit; the pack's generated HTML reports render in Preview.
  • Pin, open-external, reveal-in-Explorer, and send-to-composer actions work.

Phasing update: R13–R16 join Phase 1 — they are the front door of the "single-lane Conductor Surface" already scheduled there, and Phase 1's exit evidence now reads: a real governed run started from File → New Session, composed in the rich composer, streamed in Console mode, scored end-to-end, with zero terminal hosting. R17 joins Phase 3 beside the Profiler (the artifact index rides the same session store). If today's local work built the surface without the entry flow, the migration is additive: wrap what exists in the session document, add the sheet in front of it.
