AI-DE Conductor — Specification

version 1.0-draft date 2026-09-09 repos ai-de · ai-forward · cfd-bench status ready for local refactoring

This document specifies the evolution of AI-DE from a terminal-hosting shell into a conductor surface: an ACP client and native orchestration runtime in which one top-level agent plans, delegates, and converges work across subscription-authenticated engines, under the episode contract and Weave scoring that already exist in AiDe.Core.Watcher, with the AI-Forward Pack's goal and coordination discipline enforced mechanically and cfd-bench's grading vocabulary powering a live Agent Profiler and a routing standings board.

Decisions locked before this draft: model access is subscription-first (API keys are the recorded, off-by-default exception) · the conductor runs as a headless Claude Code session on the Max account · Antigravity is deferred to a later spike and enters as an observed lane when it lands.

1Purpose and thesis

Hosting agent CLIs as ANSI byte streams couples AI-DE to each agent's presentation. The Agent Client Protocol makes each agent's semantics — messages, tool calls, edits, permission requests, sub-session spawns — available as structured JSON-RPC, and every provider you subscribe to now ships a subscription-authenticated engine that can sit behind it (natively, by adapter, or, until then, observed through the existing terminal stack). AI-DE therefore stops being a terminal host and becomes two things: the ACP client for those engines, and the home of a Conductor — a top-level agent that owns division of labor, contention control, and convergence, with every lane's full stream persisted, scored, and navigable.

The organizing principle carries over from the rest of AI-DE: the transcript is transient; the session model — goal blocks, plans, delegation tree, decisions, evidence, scores — is the durable product, and it lives in the same workspace store and graph as the code model.

2Goals and non-goals

Goals

  • G1 — Replace terminal hosting as the primary agent surface. Two-pane Score/Performance UI over structured events; terminals remain for observed lanes and ad-hoc shells.
  • G2 — Multi-model, multi-account, subscription-first. All five provider relationships usable without API pricing; accounts are first-class; quota is the budget currency.
  • G3 — One conductor, many sub-agents. Explicit delegation tree, each lane in its own worktree, model-per-task, division of labor derived from the workspace graph.
  • G4 — Deep sub-agent observability. Navigate the tree, filter to any lane, see tool calls, edits, permissions, cost, and live quality posture; engine-internal delegation appears honestly as summary-level leaves.
  • G5 — Goal-oriented by construction. The CT19 goal block is a spawn precondition; runs close with the CT25/E18 assessment; episodes score through the existing Weave.
  • G6 — One coordination contract, two enforcement modes (governed ACP, observed CLI) on the existing Watcher plane.
  • G7 — Sessions as restartable artifacts. Blocks with context recipes; restart re-resolves late-bound against the current repo and graph.
  • G8 — Profiler and leaderboard powered by cfd-bench's vocabulary; standings feed routing.

Non-goals (v1)

  • N1 — Not an editor. Code editing stays in engines and VS Code.
  • N2 — No API-key routing by default. Metered lanes exist in config, disabled, and require explicit enablement per workspace.
  • N3 — No Antigravity integration beyond an engine-catalog placeholder; spike scheduled separately.
  • N4 — No cross-user or cloud sync. Local-first, one operator.
  • N5 — No attempt to surface engine-internal sub-agent reasoning beyond what adapters expose; depth-1..n transparency comes from conductor-level decomposition instead.
  • N6 — No change to the Weave schema. weave/1 dimensions, weights, floors, and the leaderboard partition are pinned; new material enters as cohort attributes and derived metrics only.
  • N7 — No replacement of the AI-Forward Pack. The pack remains the discipline source; AI-DE mechanizes it and must not fork its semantics.

3System architecture

Reading order for the rest of this spec: the engine plane (§4) supplies sessions; the conductor (§5) drives them; the coordination plane (§6) constrains and scores them; the session model (§7) persists them; the profiler (§8) renders them; routing (§9) chooses among them; §10 lands it all in the codebase.

4.2 Terms-of-service constraint

Anthropic prohibits third-party tools from using Pro/Max subscriptions. Consequence, enforced in code: every Anthropic-bound request originates inside a Claude Code process — sub-agent lanes and the conductor alike. The AgentPlane MUST NOT offer an Anthropic direct-api entry while a subscription account is configured.

4.3 Provider registry and accounts

  • Accounts are first-class: a lane binds to (engine, model, account), never just a provider. Quota pressure, standings cohorts, and the profiler all key on the account.
  • Secrets: AI-DE never handles subscription credentials; it shells to each engine's login and stores only account labels and probe state. API keys (opt-in) go to Windows Credential Manager/DPAPI.
  • Health probes: per account, a cheap liveness check (engine --version + a no-op session or auth-status command) with three states: ready, needs-login, quota-degraded. The router treats needs-login as absent and surfaces it in the UI.
  • Config: ~/.aide/providers.yaml (schema in §14.2); per-workspace overrides in .aide/workspace.yaml.

4.4 ACP client

  • JSON-RPC 2.0 over stdio; one child process per lane; session create passes cwd = the lane's worktree and the workspace MCP endpoint (extending McpConfigWriter) so every lane is born connected to the graph tools.
  • All ACP notifications normalize into the run event schema (§7.2). Unknown event types are preserved raw under ext, never dropped — adapters move fast.
  • Permission requests surface to the shared queue with lane identity and the plan's policy defaults (allow-list per lane from the spawn contract); "always for this run" answers persist per (lane, capability).
  • Lane teardown is supervised: on cancel or crash, the plane closes the episode as Abandoned/Blocked and hands the worktree to fail-safe cleanup (§6.4).

5The Conductor

5.1 Hosting

The conductor is a headless Claude Code session on the Max account (decision locked), created by the AgentPlane like any governed lane but with a restricted toolset: its MCP server exposes only the conductor tools below plus the existing graph tools; it has no file-edit or shell capability of its own. This enforces /execute-with-coordination's rule structurally — the coordinator cannot author track work, because it has no tools to author with.

5.3 Lifecycle

  • Stage 0 — triage (CT24): a T0/T1 run (no fan-out, no loop, no gate) skips plan and council; the conductor may satisfy it with a single lane or answer directly through report. The skip path is the common path.
  • Stage 1 — plan: graph-backed /prepare-for-coordination (§6.3), emitted via plan_submit.
  • Stage 2 — council: reviewer lanes from the persona roster with their veto semantics (Simplifier soft veto per track; Test Architect hard veto on any track without exit evidence; Tech Lead casting vote on track count). Council verdicts attach to the plan artifact.
  • Stage 3 — dispatch: spawns per approved plan; parallel only where GO5 held.
  • Stage 4 — steward: arbitrate seams and decisions; watch quota pressure; re-plan through plan_submit revisions, never ad-hoc.
  • Stage 5 — converge and close: §6.5, then close_run.

5.4 User-control semantics

  • Stop (CT21): ends current dispatch, voids any conductor-authored goal, reports state. Re-entry requires an explicit user goal.
  • Completion pressure (CT22): harness continuation nudges route to a goal-state re-read; the conductor may conclude ("done when" met) or continue toward the same goal — never adopt a new one.
  • Autonomy (CT20): run-level autonomy setting widens the how (fewer per-step confirmations) and never the what; scope admission stays at board_decide.

6.2 New episode source

GovernedSessionSource implements the same source seam as AuditLogEpisodeSource: it translates run events (§7.2) into episode opens, attribute sets, evidence-path declarations, and closes. Evidence stays observation-not-testimony: lanes declare paths; ProofPackVerifier and the converge gates go and look.

6.3 Division of labor from the graph

  • Artifact classification first. The class registry (authored / derived / register / generated) is seeded mechanically from the extractors (everything an extractor or sync tool writes is derived/generated; append-only logs are register) and extended by hand per repo. cfd-bench's grading showed the top churn in a real run was almost entirely derived artifacts — classification removes most contention before any track exists.
  • GO5 as queries. "No data edge" = no DEPENDS_ON/REFERENCES/PERSISTS_TO path between candidate scopes in the workspace graph; "no shared exclusive resource" = no shared register/single-writer artifact; "no DECISION edge" = no open board item spanning both. All three must hold for parallel dispatch.
  • Serial spine. Contract/interface nodes with cross-track in-degree are named in the plan; spine changes are board-only and freeze dependent tracks until ruled.
  • Honest multiplier. The plan states expected speedup against GO6's cost multiplier; the Simplifier's struck tracks are recorded (plan_struck_tracks) and scored up — cfd-bench measured a run where the six struck tracks were worth more than the two that ran.

6.4 Worktrees

  • WorktreeProvisioner executes AgentWorktree.Plan (sibling directory, namespaced branch), runs coord install inside the new tree (per-clone .git/config), and registers the tree with the run.
  • Fail-safe cleanup: at lane close, the provisioner deletes a tree only when it is fully merged or explicitly abandoned and has no uncommitted or unpushed work; anything else is parked and listed in the UI. Orphan sweep runs at workspace open.

6.5 Converge

  • Order = topological order of plan dependency edges; per track: proof-pack gate on declared exit evidence → merge → build/test probe in the integration tree.
  • Generated/derived artifacts are regenerated once, after the last authored merge — never merged.
  • Seams must be resolved (seam_resolution_ratio = 1.0) before the final close; unresolved seams force a Blocked outcome.
  • The converge itself is an episode and is scored; conflict commits and rework in converge feed rework_ratio.

7Session model

7.1 Files

  • Truth: append-only run log .aide/sessions/<run-id>.jsonl (schema §14.1).
  • Projection: generated, committable docs/sessions/<run-id>.md — prompts, goal blocks, recipes, decisions, closes; outputs collapsed. Same doctrine as diagrams: the log is truth, the markdown is a view.
  • Graph: runs, lanes, blocks, and decisions project into the workspace store as nodes/edges (Run, AgentRun, Block, DELEGATED_TO, PRODUCED, TOUCHED to code/table nodes) so provenance questions are graph queries.

7.2 Event schema

One normalized envelope for every source (ACP notification, conductor tool call, observed-lane audit line, OTel span): run_id, agent_id, parent_agent_id, seq, ts, kind, cost{tokens_in, tokens_out, cache_read, requests, credits?}, body, ext. Kinds (v1): run.open, block.open, goal.set, plan.submitted, council.verdict, agent.spawn, agent.msg, tool.call, tool.result, file.edit, permission.request, permission.ruling, seam.open, seam.resolve, decision, quota.pressure, episode.open, episode.close, run.close. Additive evolution only; consumers ignore unknown kinds.

7.3 Blocks, recipes, restart

  • A block = one user goal block plus everything it caused. The Score pane is the block outline.
  • A context recipe records how context was assembled — pinned paths @ commit, graph queries, block references — separate from resolved tokens.
  • Restart from block N re-resolves recipes against the current repo+graph (late-bound); prior outputs remain viewable for diffing. Resume builds the conductor's opening context from decisions and closes (or Decision nodes), not raw transcript — cross-engine by construction.

8Profiler and scoring

8.1 Grounding

The profiler adopts cfd-bench's two disciplines wholesale: claims and evidence are never merged into one column (what a lane reports vs what its artifacts show remain separate fields with the gap surfaced), and a missing measurement is "not recorded", never zero — matching AssessmentPosture.NotRecorded in the Weave.

8.3 Run-level derived metrics (adopted from cfd-bench)

Computed at close by the same extraction philosophy as grade-benchmarks.py (read what the run left behind; run the repo's own scripts from the repo's own tree): demonstration_ratio (demonstrated vs claimed outcomes — verification verbs re-executed, not trusted), verification_density, integrity_score + findings, authored_churn_ratio, rework_ratio, delegation_discipline, parallel_speedup vs peak_concurrency, seam_resolution_ratio and seam latency, fabrication_events, halt_honesty (a clean, marked halt over an integrity violation is an honest run, not a failed one), review_rigor, distinct_delegate_models. These land on the episode as attributes and on the leaderboard as cohort-visible columns; none of them alters weave/1 weights (N6).

8.4 Leaderboard extension and bench import

  • Partition stays (workspace, task class, schema version). New cohort lenses within a cell: model × engine × mode × account-type, plus the §8.3 columns.
  • Bench import: a cfd-bench run imports as scored episodes in a controlled task class (fixed benchmark prompt = fixed goal block + fixtures). Importer consumes grade-*.json + verdict.json: deterministic axes map to episode attributes; judgment axes import with their prose attached and marked judgment; axes_not_scored imports as not-recorded. Bench and live runs are then the same shape on the same board.

9Routing and standings

9.1 Modes

ModeBehavior
Pinned providerAll lanes + conductor through one provider's engine/account. (Conductor stays on Claude Code regardless — hosting decision — but with pin=anthropic it is also the only implementer.)
Pinned per roleExplicit table role → (engine, model, account). Default template: conductor→claude-code/max · implement→codex/chatgpt · review→cross-provider · utility→copilot small model.
Best fitConductor consults standings per task class, constrained by: allowed providers, live quota pressure, EgressGate policy for the repo, and floor history (a Correctness/Security floor trip in the task class deprioritizes regardless of average).
FrugalFlat-subscription lanes first; credit-metered and (if enabled) API lanes only under pressure, with the constraint recorded.

9.2 Standings computation

A projection over the leaderboard, per (task class → model × engine cohort): inputs are Weave median and spread, AIU per episode, latency, floor history, demonstration_ratio, and integrity_score; version-partitioned so a new model release starts a fresh cohort; cold-started from bench imports; recomputed on episode close. The formula is config, not code — a scored-weights file the user can tune — because ranking policy is a preference, not a truth.

9.3 Routing rationale (evidence discipline)

Every spawn_agent records routing: {mode, standing_cited?, constraint_bound?, alternatives_rejected[]}. It renders on the profiler card and lands in the episode — routing quality is reviewable, and later scoreable.

11Requirements and acceptance

R1ACP lane lifecycleP0

Create, drive, and tear down governed lanes on claude-code and codex engines.

  • Given a ready account, spawn_agent yields a live ACP session whose cwd is a freshly provisioned worktree on a namespaced branch.
  • Tool calls, edits, messages, and permission requests from the lane appear as normalized run events within 250 ms of receipt.
  • Killing the engine process closes the episode as Blocked and parks (never deletes) a dirty worktree.
  • An Anthropic direct-api spawn attempt is rejected with the ToS reason while a Max account is configured.
R2Goal block as spawn preconditionP0

CT19 mechanized for governed lanes.

  • spawn_agent without any of Goal / Done when / Not in scope / Tier / Fan-out cap / Budget fails with a field-level error.
  • Episode attributes on open equal the goal block byte-for-byte (episode.goal, done_when, not_in_scope).
  • A T0-tier run reaches dispatch with zero council lanes and zero plan artifacts (Stage-0 triage skip path works).
R3Conductor hosting and authorityP0

Headless Claude Code conductor with structurally narrow authority.

  • The conductor session's tool surface contains only §5.2 tools + graph tools; a file-edit or shell attempt is impossible by construction (not merely denied).
  • Stop voids conductor-authored goals: after Stop, the run log shows state report + no further dispatch until a user goal arrives.
  • A lane's "done/safe/in-scope" claim changes nothing until a board_decide/seam_resolve records the ruling.
R4Coordination modes unifiedP0

Governed and observed lanes coexist in one run, one scoring path.

  • A run with a claude-code lane (governed) and a grok-build lane (observed, terminal) produces episodes through GovernedSessionSource and AuditLogEpisodeSource respectively, scored by the unchanged ScoringService.
  • Mode appears as a cohort attribute; leaderboard cells never split by mode.
  • A governed lane's edit outside its lease raises a seam event automatically; the run cannot close with open seams (outcome forced Blocked).
R5Graph-backed planningP1

Division of labor derived, not guessed.

  • The class registry auto-seeds ≥ the extractor-written surfaces (derived/generated) and both audit registers; the four known-hot cfd-bench artifacts classify correctly out of the box.
  • plan_submit rejects a parallel pair with a graph data edge between scopes, citing the edge.
  • The plan artifact commits as md+html and projects into the store; struck tracks are recorded with the striking persona.
R6Sessions as artifactsP1

Persist, project, restart.

  • Every run appends to .aide/sessions/<run>.jsonl; the markdown projection regenerates deterministically (byte-identical on re-run over the same log).
  • Restart-from-block re-resolves pinned paths at current HEAD and re-runs graph queries; the diff between old and new resolved context is shown before dispatch.
  • Resume builds conductor context from decisions/closes only; token count of the resume context is reported.
R7Agent ProfilerP1

Per-lane cards + run header per §8.2.

  • Governed lanes show context bar, reasoning effort, tokens, cache share, requests, active time live (≤ 2 s lag).
  • Observed lanes show episode/audit/span counts and render capacity fields as "not recorded" — never zero.
  • Deterministic Weave dims render as signals arrive; advisory dims appear only at close; a floor trip flips the lane to Blocked within one event cycle.
  • Quota pressure per account renders in the run header and updates on 429/limit signals.
R8Derived metrics + bench importP1

cfd-bench vocabulary on the board.

  • At close, the run computes the §8.3 metric set; claims vs evidence stay separate fields with the gap listed.
  • Importing grade-20260908T204118Z.json + verdict yields episodes in a controlled task class with deterministic axes as attributes, judgment axes marked judgment, and axes_not_scored as not-recorded.
  • Leaderboard pane shows cohort lenses (model × engine × mode × account-type) inside an unchanged partition.
R9Routing modes and standingsP1

Model choice managed for user and conductor.

  • All four modes selectable per workspace, overridable per run; pinned-provider=anthropic yields zero non-Anthropic lane spawns across a full run.
  • Best-fit consults the standings projection and honors quota, egress, and floor constraints; a floor-tripped cohort is not selected even when top-ranked on median.
  • Every spawn's routing rationale is present in the run log and on the profiler card.
  • Standings weights load from config; editing them re-ranks without code changes.
R10ConvergeP1

Coordinator-owned merge per §6.5.

  • Merge order violating plan dependencies is rejected before any merge runs.
  • A track failing its proof-pack gate blocks its merge and only its dependents.
  • Derived/generated artifacts regenerate exactly once, after the final authored merge; a mid-run commit of a generated surface is flagged as classification drift.
R11Observed-lane parity for grok-buildP2

SuperGrok lane as first-class observed participant.

  • Readiness profile detects grok-build; a lane binds a terminal session to a run with role + advisory lease.
  • Its internal parallel agents surface as a single engine-internal indicator, not phantom lanes.
R12Routing-quality reviewP2

Close the loop on §9.3.

  • A periodic report correlates routing rationales with episode outcomes per task class (did best-fit's picks outscore the counterfactual cohort median?).
