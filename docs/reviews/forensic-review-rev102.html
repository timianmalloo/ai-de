FR-001 — Dirty edits can survive forced reindex as old graph evidence

P1 · issue · freshness · Verified executed. Location: src/AiDe.Core/WorkspaceCore.cs:154–160,445–498; WorkbenchShell.cs:697,791–794. Observed: Same-revision force:true reported ScopesIndexed=1, Assertions=0 and kept Probe.BeforeEdit after the file became AfterEdit. A changed-revision control emitted AfterEdit. Consequence: Graph, summaries and reviews can describe old source while reporting successful indexing. Disconfirming check: Compared both fingerprint and revision reuse layers; executed same-revision and changed-revision Core controls. Contract: Spec US-1 fresh, provenance-bearing architecture inspection; WorkspaceCore refresh promises a current scope snapshot. The executed oracle is same supplied revision, not a Git/shell run.

FR-002 — Entry-point results can exceed the IPC frame despite row clamping

P1 · issue · resource bounds · Verified executed. Location: src/AiDe.Core/Projections/ProjectionService.cs:704–730; EntryPointsProjection.cs:62–70; EveryOperationFitsTheFrameTests.cs:50–51. Observed: 1,300 facts with 2,000-character identifiers return 1,254 rows and serialize to 5,165,696 bytes against a 1,048,576-byte frame. Consequence: Large/hostile repository content can make a normal read untransportable. Disconfirming check: Inspected final return path and measured Web-default JSON payload using the same serializer family as the existing frame oracle. Contract: IpcFraming.MaxFrameBytes and ProjectionService.MaxResponseBytes are byte contracts; EntryPointsProjection itself documents that a row count is not a byte bound.
