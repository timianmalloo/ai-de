## Responsibility

`ThreadFeed` renders **one session's accepted turns, in order, above the composer** — each turn's source text, decoration line, on-demand provenance and compiled bytes, and the lane's reply folded beneath it — from **one read model**, `ISessionThread`, itself a fold over the envelope event stream and the run channel (ADR-0033 `:106-111` *"Out: `Project(Fold(events))`"*; SC1 `DESIGN.md:1116` *"derived, never a second store"*). It owns the feed's **keyboard model** (SC8), applies the **announcement policy** (SC9) through the shared `IWorkbenchAnnouncer`, and exposes **real UIA properties** (SC10). It raises requests — a turn action, a focus leave — and never mutates the session.

It is **not** responsible for: the composer (the pinned editor is the existing `ComposerSurface`, `src/AiDe.App/Workbench/Composer/ComposerSurface.cs:37`); Prepare's states and the two-gesture rule (the composer's, Addendum D §A11 `:345`; Ruling 77); the envelope store's lifetime (`SessionDocumentSurface`, ADR-0034 `:73-79`); the region cycle header → thread → composer → split (the document's, §Patterns P4); the *restoring* announcement at open (the document's, one status); or a second copy of any quantity the fold already answers (the jump list, the split, the header's count and spend are **views of the same list**).

**Boundary set:** an empty session (0 turns); one turn; forty turns with a failed past turn (`b17`, the review's fixture `:221`); four hundred turns; a running last turn streaming hundreds of event lines per second; a waiting turn (permission or cap ask) while the operator types; a turn whose `submitted` has no `consumed` (*outcome not recorded*, ADR-0034 `:82`); a read model whose `Changed` fires twice with identical state; a `Changed` raised off the UI thread (`ConsoleStreamModel.cs:184-186` does); two `Changed` arriving before one render; a read model that skips a version (a contract violation); a compile event (`Kind = compile.*`, `Ext.origin = "compile"`, ADR-0033 `:226-235`) shown under its envelope's turn and never counted as a run; a 12,000-character source text (≈ 2,400 px tall at 96ch — taller than the 575 px viewport); a reply containing `<a href>` and markdown (rendered as plain text, Addendum D `:369`); a reopened 40-turn session whose store walk delivers the history in forty snapshots **before** the catch-up flag (nothing is announced); the operator reading `b17` while the editor is still starting; a fold opened on `b3`, then `b38` reusing its container (Q13); a 30-line compiled prompt in the pinned composer (Q14).

## Contracts

### Exposed (what the thread offers)

```csharp
// src/AiDe.App/Workbench/Sessions/FeedList.cs — the shared base (P1, P2, P7): ~80 lines, two consumers
public abstract class FeedList : ListBox, ICanvasFocusTarget
{
    // P1 in the constructor: IsVirtualizing, Recycling, ScrollUnit=Pixel, CanContentScroll, UseLayoutRounding,
    // ink and ground by resource reference, the container template, the keyed disclosure style.
    public static bool SourceOwnsItsKeys(DependencyObject source);          // a ScrollViewer or a TextBoxBase in the source's ancestry inside this list
    public FeedKeyDecision Decide(Key key, ModifierKeys modifiers, bool sourceOwnsItsKeys);   // PURE (K1a): MoveBy(±1) | MoveTo(first|last) | Scroll(±3 lines) | Leave(ToHeader|ToEditor) | None
    protected bool Act(FeedKeyDecision decision);                             // the act (K1b): select → ScrollIntoView → UpdateLayout → container.Focus(); or ScrollToVerticalOffset; or raise the leave
    public bool FocusCurrentItem();        // ICanvasFocusTarget.TryFocus: scroll the caret's item into view, then focus its container
    public bool FocusCurrentItemLast();    // backward entry: the caret's item's last tab stop
    public bool FocusItem(int index);      // lands on the CONTAINER, never an inner control
    public event Action<FocusLeave> FocusLeaveRequested;                    // ToHeader (Ctrl+Home) · ToEditor (Ctrl+End)
    // private: the structural pin (IsPinnedAtEnd), the GotKeyboardFocus re-route, the scheduled-flag flush
}

// src/AiDe.App/Workbench/Sessions/ThreadFeed.cs — the turn feed
public sealed class ThreadFeed : FeedList, IDisposable
{
    public ThreadFeed(ISessionThread thread, IWorkbenchAnnouncer announcer);   // the policy is constructed inside (A1 tests it pure, without a feed)
    public bool FocusTurn(int ordinal);                                        // the jump list's Enter; the "b1 is running" link
    public bool IsStopped { get; }                                             // the feed's own fault state (THR-0001): ItemStatus "stopped"; "live" otherwise
    public event Action<TurnAction> TurnActionRequested;                       // one channel for every act on a turn; SendAgain and UseAsNextDraft end with FocusLeaveRequested(ToEditor)
}

// the split — the same base over lines, no subclass: FeedList configured with the line template, name and ItemStatus (§The control's shape)

public enum FocusLeave { ToHeader, ToEditor }
public enum TurnActionKind { Stop, Deny, AllowOnce, AllowThisTurn, OpenSessionSettings, SendAgain, OpenLog, UseAsNextDraft, OpenConsoleAt }
public sealed record TurnAction(int Ordinal, TurnActionKind Kind, string? RequestId);
```

Guarantees: every public member is UI-thread only (WPF); `Decide` **never throws** for any `(Key × ModifierKeys × bool)` and returns `None` for keys the feed does not own, for Ctrl+PageUp/PageDown (the pane switch, `WorkbenchController.cs:789-794`), and when the source owns its keys — but it **owns the six keys from an inner control too** (from *Deny* or *provenance ▸*, PageDown is the next turn, never the `ListBox`'s page jump — the falsified platform navigation must not re-enter through an inner stop); `FocusCurrentItem` returns `false` on an empty list (the document then focuses the one focusable text outside the list, whose words are *Restoring <name>…* until the read model is caught up and *Nothing has run yet.* after); the caret is the last item on open and is restored by ordinal across re-renders; a row is updated **in place** (Q10) so a realized container, its focus and the caret survive every `Changed`; **every snapshot reaches the announcement policy in `Version` order — only the render coalesces**; the announcer is called **after the render** (a second dispatcher operation posted after the merge — the render pass runs between them at its higher priority; DC-077 `:2646`); before an action's button is disabled or removed, focus moves to the turn's container (never dropped to the window).

## Data model (settled before the contracts — DM1–DM18)

**Bounded context.** The **session conversation** is the *read side* of two contexts it does not own: Prompt Compilation (ADR-0033; the envelope aggregate, one invariant *it only grows*, ADR-0034 `:43-47`) and the run channel (`RunEvent`s per lane). Ubiquitous language: **turn** (an *accepted* submission — `submitted.accepted = true`; a refusal before start is not a turn, Addendum D E6 / SC7), **ordinal** `b<n>` (dense, 1-based, assigned at accept), **decoration** (a row of the envelope with its `source`), **outcome** (the `consumed` row's word: *answered · completed · lane exited n · stopped by you*; *waiting for you* is a live state, never an outcome — E6), **event line** (one `RunEvent` of the turn's run), **fold** (the events collapsed under a completed turn), **split** (the same events unfolded in time), **snapshot** (the read model's state after one applied event, versioned), **caught up** (the store walk has finished; what follows is live).

**Aggregates touched, by identity only.** The thread holds **no aggregate and no durable data**. It references envelopes by `envelope_id` and runs by `run_id`; both live in their own stores (ADR-0034 `:21-23`; the run channel). One aggregate per transaction is trivially met: the thread has no transactions.

**The read model's grain.** *One `TurnView` is exactly one accepted turn of one session, identified by its ordinal (and its `envelope_id`), recorded when the conductor accepts it.* Its fields are projections of the envelope fold joined to the run channel on `run_id` (`submitted.run_id` ↔ `RunEvent.RunId`; a `compile.*` event joins on `Ext.envelope_id` and is shown under that turn, never counted as a run — ADR-0033 `:226-235`). *One `ThreadSnapshot` is exactly the read model's state after one applied event, identified by `Version` (0 = the folded history at catch-up).*

| Measure on the outcome line / header | Class | History rule | Derivation and its writer / reader |
|---|---|---|---|
| edits (files touched) | additive across turns | append-only (a new `consumed`/event, never a rewrite) | Σ of the run's edit events; reader: the outcome line |
| tokens in / cached / out | additive across turns → **session spend in the header** (Ruling 78) | append-only | from `RunEventCost` per run; **absent `usage` → *not recorded*, never 0** (Ruling 78 condition 1) |
| requests | additive | append-only | per run |
| duration | additive across turns **under Ruling 77** (one run at a time; if parallel runs are admitted it becomes semi-additive and the session total is wall-clock — recorded) | append-only | run start → `consumed.at` |
| events (count) | additive | append-only | the run's `RunEvent` count |
| the turn's state | non-additive | the latest `consumed` wins; `NotRecorded` when `submitted` has no `consumed` (ADR-0034 `:82`) | reader: the outcome line, the jump list, the announcement policy — **one encoding** (`TurnState` + `ExitCode`), never a parallel word |
| `Version` | non-additive, monotonic | +1 per applied event after catch-up | writer: the read model; readers: the control (order, gaps), M4 / R1 |

**Type-2 by construction:** every attribute of a `TurnView` is a fold over an append-only stream, so a past record is never rewritten. **Derive, don't store:** the jump list rows, the split rows, the header's `n turns` and spend, the in-flight turn, the restoring caption and the caret are computed from the snapshot; the only materialised copies are the `TurnItem` rows (a rebuildable projection of `Turns` plus the three disclosure flags, equal by construction — C1's merge row) and the panel's realized containers (WPF's own). **No schema change** — nothing is persisted (no migration; the Data & Persistence veto is not triggered).

**The caret is view state**, not model state: it is `ListBox.SelectedIndex`, the last item on open, restored by ordinal across merges, never written anywhere.

**Overlays, the rule:** every overlay in the session document is a `Popup` (its own HWND — the jump list, the session settings, tooltips) **or** is confined to rows 0–1 (the outside text, the boxed reason, the stopped row); no `Effect`, `Opacity < 1` or `BitmapCache` on any element that can overlap the composer's row (ADR-0015; `SurfaceChrome.cs:12-16`; ClearType survives only on an opaque ground).

**The follow rule (P7).** On every snapshot the control reads the structural pin *before* the merge; after the layout it calls `ScrollToEnd()` only if it was pinned. A turn joining announces itself (SC9) and moves nothing else (`DESIGN.md:1131` — 0 ms).

**The 40-turn measure.** *`realized(40) < 40`*, *`realized(400) < 400`* and *`realized(400) − realized(40) ≤ 2`* (measured 8 and 9 on the stand-in — the count tracks the viewport, not the item count; virtualization off realizes 40 and 400, Q15); the counts are reported in `thread.layout`, never asserted absolutely. ## SC9 — the announcement policy (item 3)

`ThreadAnnouncementPolicy.Next(snapshot)` (Core, T0, an instance holding the previous snapshot): a snapshot before catch-up → nothing remembered, nothing emitted; the first caught-up snapshot → remembered, nothing emitted (history is not news); every later snapshot → for each ordinal whose `(State, Waiting?.RequestId, Outcome?.ExitCode)` differs from the previous snapshot, the row of the **total** table below, in ordinal order. The control feeds **every** snapshot in `Version` order (the render coalesces, the policy does not) and forwards each emission to `IWorkbenchAnnouncer.Announce(Announcement)` **after the render**. Two snapshots arriving before one render yield both transitions; two outcomes in one snapshot yield two announcements (both `Status` → `All`, queued). A `Version` gap is a contract violation (`THR-0003`): the net transition per ordinal is still announced, the state the read model hid is not — a recorded, tested consequence.

## Error & concurrency model

- **Threading.** `Changed` may arrive off-thread and carries its snapshot; the handler enqueues the argument (never reads `Current` back) and posts **one** dispatcher operation while none is pending (a scheduled-flag flush, `Interlocked.Exchange`; 500 raises post one operation, not 500). `Apply` runs at `Background`: it drains the queue **in `Version` order**, feeds every snapshot to the policy, merges the **latest** into the rows, lays out once, and posts a second `Background` operation that announces the collected emissions — the render pass runs between the two at its higher priority (DC-077). A snapshot is an immutable record, so a producer publishing during `Apply` cannot tear it (DC-062 prevented by immutability). The control subscribes once (constructor) and unsubscribes in `Dispose` (the DC-032 audit).
- **Ordering and gaps.** Raises are serialized by the read model (one producer at a time); a `Version` that is not `previous + 1` is a contract violation: `THR-0003` logged with both versions, the snapshot still applied and diffed (the net transition is spoken; the hidden state is not).
- **Idempotency.** `Apply` merges by ordinal into `TurnItem` rows (P5); the same record → no-op; announcements are by transition (P6).
- **Cancellation / lifetime.** `Dispose` unsubscribes and drops the `ItemsSource`; the document owns the read model's lifetime (ADR-0034 `:73-79` for the store). A `Dispose` between the post and `Apply` is safe: `Apply` checks `_disposed` first.
- **Errors.** `TurnView`'s invariants are enforced in its constructor (Core, T0 — the projection's tests catch them; nothing reaches the dispatcher). An `Apply` that throws is caught: `THR-0001` logged with `exception.type`, `IsStopped` = true, the visible stopped row shown (outside the scroller) and its assertive announcement raised — the channel survives (DC-134). A refused `CycleRegion` is a `CanvasFocusResult.Refused` with its announcement (`THR-0002` on the record), never a silent no-op.
