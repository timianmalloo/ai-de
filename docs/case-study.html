Context & Objectives

The Project Intent: Code is Transient, Navigation is Permanent

Why AI-DE was conceived and how it re-imagines the developer experience for an era of generative code.

Traditional IDEs (VS Code, Visual Studio, JetBrains) were built on an implicit assumption: code is precious, written slowly by human fingers, and best browsed as a static tree of text files.

AI-DE flips this paradigm upside down:

  • Generated Code is Transient: Agents can generate, refactor, and mutate thousands of lines in seconds. Reading raw syntax files becomes a bottleneck.
  • The Repository as a Semantic Model: Instead of navigating text files, AI-DE loads the entire codebase into a living, queryable semantic model using Roslyn workspaces, AST graphs, and durable fact stores.
  • Multi-Faceted Viewers Over the Model: The IDE provides high-speed, interactive views: a live Semantic Code Atlas, an infinite reactive Canvas Dock (filling 93.1% of the viewpane), and structured agent conversation streams.

Engineering Scale: Over 4 weeks, AI-DE grew from a blank repo to an enterprise-grade WPF desktop application on .NET 10, comprising 596 source files (94,015 LoC), 500 test files (99,838 LoC), and 3,810 passing xUnit tests.

Philosophy & Mindset

The Paradigm Shift: From Ad-Hoc Scripts to Enterprise TDD

How AI-Forward discipline enabled rapid velocity without succumbing to technical debt.

Naive Desktop AI Development Fragile
  • Single monolithic WPF window handling UI, state, and compiler invocations.
  • Direct UI thread blocking during long-running Roslyn AST compilations.
  • Manual F5 debugging to see if controls render correctly.
  • Blindly accepting heavy graph database dependencies (e.g. Kuzu).
  • Writing code first, postponing tests until "later".
AI-Forward Systems Engineering Deterministic
  • Strict Domain & Data Modeling (DM1–DM18): Fact stores, append-only events, immutable Roslyn snapshots.
  • The "Step Back" Move: Ruthlessly tearing down flawed drafts (e.g. superseding v1 architecture with v2).
  • Spike-Driven Validation: Running empirical spikes on MSBuildWorkspaces, DPI awareness, and WebView2 interop.
  • Strict Red-First TDD: Over 99,800 lines of tests written before implementations were accepted.
  • Multi-Agent Coordination: 93 parallel coordination runs dividing Atlas, Canvas, and Conductor tracks.

Architectural Mastery

The Architecture v2 Pivot: Decoupling Daemon from Shell

How questioning the initial monolithic design prevented catastrophic UI performance degradation.

Early architectural drafts assumed that Roslyn workspace management, AST indexing, and WebView2 canvas rendering could comfortably run in the same process as the WPF application.

In Change Log #5, the user halted execution: "step back / /define-architecture ai-ide-arch-v2 — use the spec, the original architecture.md and your findings as input; adopt the local workspace daemon and fact-store architecture."

Architecture v1: In-Process Monolith Rejected
  • Roslyn solution compilation ran in WPF application domain.
  • Garbage collection pauses from Roslyn symbol trees froze UI animation.
  • Crash in Roslyn compiler crashed the entire editor.
  • External graph database (Kuzu) added C++ native binary dependency.
  • No clean separation between agent orchestration and editor state.
Architecture v2: Workspace Daemon + Fact Store Adopted
  • Local Workspace Daemon: Runs as an independent background process on .NET 10.
  • Named Pipe RPC: High-throughput binary messaging with zero UI dispatcher contention.
  • Append-Only Fact Store: Transient code changes streamed as delta events rather than full solution reloads.
  • Zero Native C++ Bloat: In-memory indexed relations replace external graph databases.
  • Fault Isolation: A daemon crash is recovered without losing unsaved editor state.

The Rigor Engine: 3,810 xUnit Tests in Strict TDD

Maintaining an unmatched 1:1.06 test-to-code ratio in enterprise C# WPF.

Many teams struggle to test desktop WPF applications, often settling for manual testing. AI-DE rejected this compromise:

  • 2,756 Core Tests (AiDe.Core.Tests): Testing Roslyn solution compilation, named pipe RPC protocols, fact-store event sourcing, and AST query resolvers.
  • 1,054 App Tests (AiDe.App.Tests): Testing ViewModels, asynchronous data bindings, command dispatchers, and dock layout algorithms.

Playbook

The 6 Core Tenets: The AI-DE Blueprint

Essential rules for building large-scale, complex software systems with AI coding agents.

01
Ground Before Scaffolding
Invest in domain research (/collectknowledge) before creating project templates. Understanding Roslyn's immutability saved AI-DE from months of synchronization bugs.
02
Specify the Three Layers
Every feature must define Functional boundaries, UX interaction flows, and UI layout constraints. Ambiguity in UX leads to rewritten UI controls.
03
Embrace the "Step Back"
Do not hesitate to tear down a flawed v1 architecture. Sunk cost fallacy is deadlier with AI; discarding a bad draft and regenerating a clean v2 takes hours, not months.
04
Decouple Compute from Shell
In AI tools, semantic indexing and background analysis must be isolated out-of-process. Never let heavy AST traversals block the user interface.
05
Treat Tests as the Primary Asset
In an era where code is transient, your test suite is the only enduring truth. Maintain a 1:1 test-to-source ratio to give agents freedom to refactor fearlessly.
06
Automate the Join Gates
Multi-agent parallelism works only when merge gates are strictly enforced. Never merge unverified code to main.
